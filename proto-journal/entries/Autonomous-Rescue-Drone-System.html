專案概念

設計一套以電池動力為主、能持續執行多輪任務的自主無人機系統。首個使用情境是消防隊到達前的初期火點支援：在安全及法規允許的條件下，協助偵察、定位、運送少量水或適用載荷，並自動返回補給站。

核心目標：自動化整個任務循環，而不只是讓無人機自動飛行。系統應能接收任務要求、評估可行性、選擇載荷與路線、執行任務、確認結果、返航、補給、自主更換電池、檢查狀態，並在條件允許時開始下一項任務。

設計原則

  • 任務導向：依照任務目標、距離、載荷、時限、環境與風險決定執行方式，而不是固定只執行一種任務。
  • 全流程自動化：涵蓋任務規劃、派遣、飛行、載荷操作、返航、補水、換電、健康檢查及任務紀錄。
  • 模組化：任務規劃、飛控、感測器、載荷、補給站及能源管理使用清楚的介面分離。
  • 安全優先：自動化不代表無限制自主。遇到低電量、失聯、定位異常、天候不適合或任務風險超標時，系統必須中止、返航或進入安全狀態。
  • 逐步驗證：先建立軟體模擬，再進行飛控模擬、地面補給測試、無載荷飛行與受監督的載荷測試。
  • 不預設任務上限：架構允許未來加入偵察、巡檢、測繪、物資運送等任務，但每種任務都必須先定義載荷、能力、法規與安全驗證條件。

第一個任務情境：初期火點支援

  1. 接收火點位置、任務優先級、可用時間與作業限制。
  2. 取得或確認火點資訊，評估航線、天候、禁飛區、電池餘量及補給站狀態。
  3. 選擇合適的無人機、載荷與任務策略；若條件不符合安全門檻，拒絕派遣並回報原因。
  4. 自動執行已批准的航點任務，在允許條件下完成偵察或載荷投放。
  5. 確認任務結果並記錄影像、位置、耗電、載荷狀態與異常事件。
  6. 返回補給站，降落、補水或更換任務載荷、自主更換電池，並執行機體健康檢查。
  7. 系統重新計算可執行任務；通過所有檢查後才進入下一輪。

無人機所攜帶的水量有限，實際效果會受火勢、燃料、風況及投放精度影響。本專案定位為消防隊到場前的輔助系統，不宣稱小型無人機可以取代消防車或處理大型森林火災。

模擬器與測試工具模擬飛行、耗電、載荷、補給、故障與多機排程。先以可重複的模擬測試驗證任務流程。

自主換電與補給站

預期流程

  1. 無人機降落並確認已停止旋翼，補給站確認機體位置及固定狀態。
  2. 讀取電池識別碼、健康狀態、溫度及可用性；不接受不符合規格的電池。
  3. 使用機械機構安全移除舊電池，確認舊電池已完全脫離。
  4. 取出符合機型、電壓、容量及健康門檻的備用電池並完成插入、鎖定及電氣連接檢查。
  5. 執行電池通訊、電壓、溫度及飛控狀態檢查；任何驗證失敗都禁止起飛。
  6. 執行補水或載荷更換，確認液位、重量或載荷識別結果。
  7. 完成機體、旋翼、感測器、通訊及任務區域檢查後，回報可再次派遣。
設計限制：自主換電是高風險機械與電氣整合工作。初期應使用人工換電或地面測試架驗證介面；在機械鎖定、電池辨識、斷電保護與異常復原未通過測試前，不應讓機構在無人監督下操作真實飛行電池。

載重與續航：目前的假設

項目初期研究目標驗證方式
水載荷以 2–5 L 作為概念原型的初始研究範圍，不視為已驗證的消防規格。確認整機起飛重量、重心、結構與滿載耗電；先做地面載荷測試。

補給時間分別量測降落、固定、換電、補水、檢查與再次起飛時間。多輪重複測試，統計平均值及最差情境。
任務效率以每小時成功完成的任務數、有效載荷量及安全中止率評估。用任務日誌和模擬資料計算，避免只看飛行分鐘數。

軟體實作方向

  • Runtime：Node.js / TypeScript，負責任務管理、資源管理、事件處理與系統整合。
  • Flight control：評估 PX4、MAVLink 及對應模擬器；即時飛行穩定與失效保護留在飛控層。
  • Dashboard：使用 Web 前端顯示地圖、機隊狀態、任務佇列、補給站及告警。
  • Storage：保存任務、遙測摘要、電池循環、載荷、維護、錯誤及復原紀錄。
  • Communication：定義命令、回報、逾時、重試、去重及斷線後狀態同步規則。
  • Simulation：先建立可注入故障的虛擬無人機與補給站，不依賴真實硬體即可測試流程。

不限制任務：能力與任務插件

系統不應把「消防」寫死在核心流程。核心負責資源、安全、任務狀態與排程；每一種任務透過插件定義自己的需求與執行步驟。

任務插件可能用途需額外驗證的能力
Fire Support火點偵察、初期火點輔助處置熱成像、火場風險、載荷控制、消防單位協調
Reconnaissance災區影像、狀況回報、路線偵察影像品質、定位準確度、通訊與隱私
Inspection設施、屋頂、管線或環境巡檢感測器、飛行路線、障礙物與作業許可
Mapping地形或災區資料蒐集測繪精度、相機校準、資料處理
Supply Delivery運送已核准的輕型物資重量、固定、投送方式及地面人員安全

「不限制任務」代表架構可擴充，不代表任何任務都能自動執行。每個插件必須聲明所需硬體、允許環境、載荷限制、風險等級、成功條件及中止規則；未通過能力與安全驗證的任務不得派遣。

風險與控制方式

風險可能影響控制方式
電量估算錯誤無法返航或被迫緊急降落以實測建立保守模型，保留返航與異常處置電量；飛控獨立監控低電量。
換電失敗電源中斷、短路或電池脫落機械互鎖、電池識別、鎖定回饋、電氣檢查與禁止起飛條件。
補水故障或洩漏載荷不足、電子設備進水或重心改變液位與重量交叉檢查、防水隔離、洩漏檢測與補給失敗復原。
通訊中斷任務狀態失去同步飛控獨立失效保護、命令逾時、事件日誌及重新連線同步。
定位或感測器失效偏離航線或誤判火點健康檢查、多來源交叉驗證、限制操作區域及安全中止。
多機資源衝突航線衝突或補給站排隊任務鎖定、資源預約、空域隔離與排程器檢查。
環境不適合強風、熱流、煙霧或能見度影響飛行定義可接受環境門檻；超出門檻就拒絕出動或中止。
錯誤任務要求派遣不合能力或不安全的任務任務能力驗證、權限控制、任務範圍限制與審核流程。

開發階段

Phase 1 — Mission Simulator

  • 建立任務、無人機、電池、載荷及補給站資料模型。
  • 實作任務狀態機、派遣條件、返航判斷與故障事件。
  • 模擬補水、換電、充電排隊及多任務排程。
  • 建立 Web Dashboard 與可重播的任務日誌。

Phase 2 — Flight Simulation

  • 整合 PX4 SITL 或適合的飛控模擬環境。
  • 測試航點、返航、低電量、失聯與任務中止。
  • 模擬錯誤感測值、站點不可用、換電失敗及通訊恢復。

Phase 3 — Ground Station Prototype

  • 建立無人機停靠、固定、電池辨識及補水的地面測試架。
  • 先在不連接飛行器的條件下驗證換電機構與安全互鎖。
  • 測試感測器回饋與控制器失效時的安全狀態。

Phase 4 — Supervised Flight Tests

  • 在合法且受控的場地進行無載荷飛行與返航測試。
  • 逐步加入經核准的測試載荷，量測重量、重心及能耗。
  • 在專業監督下測試自動對接、補給與任務復原。

Phase 5 — Multi-Mission Operations

  • 驗證多種任務插件與能力宣告機制。
  • 加入多機派遣、補給站排程及任務優先級管理。
  • 根據真實測試資料調整任務模型，形成可審核的運行程序。

第一版完成條件

  • 可以建立、驗證、派遣、取消及完成一項模擬任務。
  • 任務不可行時，能回報具體原因而不是盲目出動。
  • 模擬器能處理低電量、失聯、補水失敗、換電失敗及站點不可用。
  • 只有在補給及健康檢查成功後，無人機才會進入 READY 狀態。
  • 所有狀態變化、命令、異常與復原步驟都有時間戳記錄。
  • 飛控失效保護不依賴 Web Dashboard 或雲端服務正常運作。
  • 任務插件可新增，而無須重寫核心任務循環。

尚待研究的問題

  • 機型、最大起飛重量、有效載荷與滿載耗電量。
  • 電池規格、電池更換機構、充電策略及電池健康管理。
  • 補水接口、過濾、防漏、液位量測及水箱防晃設計。
  • 實際任務距離、風況限制、返航餘量與每小時任務吞吐量。
  • 感測器、避障、熱成像與火點確認策略。
  • 馬來西亞適用的無人機操作許可、空域限制、消防協作及測試要求。
  • 任務插件的安全分類、授權機制與可追溯性。

結論

本專案的核心不是單一消防無人機，而是一套可以自動管理任務、飛行、能源、載荷、補給與復原流程的模組化自主系統。消防輔助是第一個驗證場景；長期方向是讓系統依照每項任務的要求，自行判斷能力、安排資源、執行工作並確認結果。

第一個可交付成果：先建立 Node.js 任務模擬器與補給站狀態機，讓「任務完成 → 返航 → 自主換電與補給 → 健康檢查 → 再次派遣」在模擬環境中完整運作，再逐步連接真實飛控和硬體。
